# Security Policy

## Supported Versions

Security fixes are applied to the latest release on the default branch. Older
releases are not supported unless a release note explicitly states otherwise.

## Reporting a Vulnerability

Do not open a public issue for a suspected vulnerability or include secrets,
credentials, patient information, or production logs in a report. Use the
repository host's private security advisory feature to contact the maintainers.

Include the affected version, reproduction steps, impact, and any proposed
mitigation. Use synthetic data only. The maintainers will acknowledge the
report, assess severity, and coordinate disclosure after a fix is available.

## Scope

Reports about authentication, authorization, sensitive health information,
file handling, encryption, dependency vulnerabilities, and AgentTeams
integration boundaries are in scope. Vulnerabilities in separately deployed
third-party services should be reported to their respective maintainers.
